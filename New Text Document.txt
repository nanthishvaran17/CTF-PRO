ROLE
Act as a senior security engineer, CTF specialist, full-stack architect and
product designer. Build CTF HUNTER X end to end, autonomously, in ONE run:
a local-first, evidence-based CTF analysis and flag discovery platform for
authorized CTF files and environments only. Do NOT stop for approval between
phases. Work continuously until the Definition of Done is fully met.

=====================================================================
0. ABSOLUTE RULES
=====================================================================
- No fake flags, no mock results, no hardcoded demo findings, no simulated
  analysis, no placeholder algorithms, no non-functional buttons.
- Every result comes from real input + real execution. If a tool is missing,
  show "unavailable" and use a real Python fallback; never fake output.
- Original files are read-only. Record SHA-256, size, true type (magic bytes),
  byte offsets, extraction paths, every transformation.
- No confidence percentages unless the formula is defined. Use explainable
  evidence reasons.
- Flag statuses: DISCOVERED, CANDIDATE, EVIDENCE-SUPPORTED, VALIDATION-PENDING,
  VERIFIED-BY-CHALLENGE (only after authoritative platform/organizer
  confirmation), REJECTED, UNRESOLVED.
- Test fixtures exist only in tests/ and are never shown as real discoveries.
- Never claim anything is done/passing without actually running it and
  showing real output. If something cannot be implemented, list it under
  "Limitations" in README and in reports.
- Only authorized targets. No internet scanning. SSRF-safe web module.

2. STACK AND ARCHITECTURE
=====================================================================
Backend: Python 3.11+, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, SQLite
(local) / PostgreSQL (production), background job queue with isolated worker
processes, structured logging, API versioning (/api/v1).
Frontend: React + TypeScript + Vite + Tailwind, PWA, responsive, accessible.
CLI: `ctfx analyze <path>`, `ctfx report <challenge>`, `ctfx tools`.
Platforms: Windows, Linux, Kali, macOS, Docker, localhost browser, optional
remote server. No admin rights needed. Kali not required.
Modes: LOCAL (no login) and REMOTE (auth, sessions, CSRF, rate limit, audit).
Plugin system: any Python file in plugins/ implementing the Analyzer interface
is auto-loaded and appears in UI.
Repo: backend/, frontend/, plugins/, tests/, docs/, scripts/, docker/,
.github/workflows/. Start by writing the repo tree + threat model in docs/.

3. FILE INTAKE
=====================================================================
Drag-drop, multi-file, folder, archive upload; size reporting; magic-byte
type detection (PNG, JPEG, GIF, BMP, TIFF, WEBP, SVG, PDF, DOCX, XLSX, PPTX,
ZIP, TAR, GZIP, 7Z, RAR, TXT, JSON, XML, HTML, CSV, PCAP, PCAPNG, ELF, PE,

Streaming reads; never load large files fully into memory.

=====================================================================
4. FLAG DISCOVERY ENGINE
=====================================================================
A. Direct detection: configurable regex (FLAG{}, CTF{}, custom event
   formats), case options, unicode, multiline, binary scan, nested and
   extracted files. Do not assume standard format. Auto-detect flag format
   from challenge description / event name when provided.
B. Strings: ASCII, UTF-8, UTF-16LE/BE, null-separated; record file, offset,
   encoding, content, method.
C. Decoder: Base64/32/16, hex, URL, HTML entities, ROT13, Caesar, binary,
   ASCII decimal, unicode/JSON escapes, UTF-8/16, single-byte XOR, common
   substitution. Multi-layer with max depth, cycle detection, output size
   limit, full transformation history, provenance.
D. Hidden data: metadata/EXIF, embedded files, trailing bytes, hidden archive
   entries, extension mismatch, null regions, entropy, appended data. Use
   binwalk/exiftool/file/strings/7z when present, Python fallback otherwise.
   Never claim hidden content without evidence; say "nothing found" when
   nothing found.

=====================================================================
5. ANALYSIS MODULES
=====================================================================
STEGO: PNG chunks, LSB, bit-planes, RGB/alpha channels, palette, image
entropy, odd dimensions, embedded files, image compare, OCR, QR/barcode.
AUDIO (WAV/MP3/FLAC/OGG): metadata, spectrogram, waveform, frequency view,
transcription if supported. VIDEO: metadata, frames, OCR on frames, audio
track, subtitles, embedded files (ffmpeg).
FORENSICS: PCAP/PCAPNG (Scapy/TShark): protocols, TCP stream reconstruction,
HTTP/DNS/FTP/SMTP/TLS metadata, file extraction, credentials in challenge
captures, payload flag scan, stream evidence. Logs (auth, web, app, Windows
event, syslog, JSON, CSV): timeline, timestamp normalization, correlation,
suspicious events, flag search. Memory dumps: strings, process artifacts,
Volatility if present, honest limits otherwise.
CRYPTO: Caesar, ROT, Atbash, Vigenere, XOR, repeating-key XOR, base/hex/
binary, frequency analysis + charts, substitution analysis, hash ID +
compare, RSA/AES educational helpers (small/weak keys, common modulus,
etc.). Never claim a result without valid derivation; unknown encryption is
reported as UNRESOLVED.
WEB (authorized targets only): URL parsing, headers, cookies, HTML/JS/CSS
inspection, robots/sitemap, forms, source maps, static JS analysis, endpoint
extraction from supplied content, DevTools guidance, flag search. Guided
safe workflows for auth, input validation, SQLi/XSS/IDOR/path traversal/
SSRF/JWT/API/file-upload labs. No scanning, SSRF-protected fetcher.
REVERSE ENGINEERING: ELF/PE/Mach-O parsing, architecture, imports/exports,
sections, symbols, strings, basic disassembly, suspicious functions,
radare2/Rizin/Ghidra/objdump/readelf hooks. Execute binaries ONLY in
sandbox (container/limited process: no network, CPU/RAM/time limits).
OSINT (public data only, rate-limited): image metadata, reverse-search
guidance, geolocation clues, domain/DNS/cert info, username correlation,
document metadata, timestamp analysis.

=====================================================================
6. VERIFICATION ENGINE (most important)
=====================================================================
Per candidate store: text, source file, source SHA-256, byte offset,
encoding, extraction method, transform chain, original evidence ref,
discovery time, challenge id, status, explainable reasons.
Decoy detection: README/doc examples, placeholders, known samples, repeated
unrelated strings, irrelevant files, synthetic data; shown as explainable
reasons; NEVER auto-reject a valid flag just because it looks like a
placeholder. Authoritative validation: event-specific format rules,
organizer validation, official platform submission with response capture
(accepted/rejected stored in verification_events). Never mark VERIFIED
without it.

SIGNATURE FEATURES
1. Evidence Graph: file -> extraction -> decode step -> candidate (clickable).
2. Reproduce Script Export: exact CLI/Python commands to repeat every finding.
3. Auto Writeup Generator: Markdown from the real evidence chain only.
4. Smart Triage: rule-based "next steps to try" from file type + description,
   with reasons, no fake scores.
5. Hex <-> Evidence deep link: click candidate -> hex viewer jumps to offset.
6. Flag-format auto-detect.
7. Plugin system.
